# 新浪行情接口（`hq.sinajs.cn`）代码前缀与字段速查

`tools/push_auto.py` 取行情用的就是这个接口。这份文档记录**实测**得到的前缀、字段布局与坑，
供以后加标的时先查这里、再用文末的脚本复核。

> 本文所有「实测」标记的数据都是 2026-09-29 用标准库 urllib 直接打 `hq.sinajs.cn` 抓的
> 原始响应，来源见每节的响应片段。凡是**没有**实测过的，明确写了「未实测」，不要当结论用。
>
> §3.6~§3.8 引用了社区字段表 `https://alanhere.com/2019/06/11/sina-stock-api`（下文简称
> **社区文档**）作为线索，但**每一条都以本文自己的实测响应为准**，社区文档与实测冲突时
> **以实测为准**（已发现两处：§3.7 里社区表格的 `1.176` 是笔误，样例值应为 `1.76`；
> §3.6 的延迟 15 分钟是社区文档的说法，**延迟幅度本身本项目未独立验证**）。

## 1. 端点与三个必需条件

```
https://hq.sinajs.cn/list=<代码1>,<代码2>,...
```

| 条件 | 值 | 不满足的后果 |
|---|---|---|
| `Referer` | `https://finance.sina.com.cn` | **HTTP 403** |
| `Accept` | `*/*` | 部分环境下被拒 |
| `User-Agent` | 常规浏览器 UA | 可能被拒 |
| 响应编码 | **GBK / gb18030**（不是 UTF-8） | 中文名乱码 |

响应是一行一条，形如：

```
var hq_str_<key>="<逗号分隔字段>";
```

`<key>` 就是请求里的代码（`s_` 简版请求则是 `s_<code>`）。**行序 = 请求序**。

> `rn=<随机数>` 破缓存是社区常见做法（easyquotation / akshare / tushare 都加）。**我们没加**：
> 实测同一个 URL 每 20s 连打 5 次、跨过连续竞价开盘时刻，5 次里有 3 组取值不同 → 中间 CDN
> 没有缓存我们的轮询 URL。`--stock-dry-run` 可自行复验。

## 3. 八种已识别形态的逐下标布局

> §3.1~§3.5 = 会**出行**的形态（推给设备）；§3.8 外汇 = **只识别、跳过**，不出行。

### 3.1 `s_` 简版 —— 6 字段
```
var hq_str_s_sh000300="沪深300,4332.9418,-7.8132,-0.18,748503,850000000";
                     [0]名称 [1]点位 [2]涨跌额 [3]涨跌幅% [4]成交量 [5]成交额
```
- **`f[3]` 就是涨跌幅百分比，不用自己除。** 算术自校验：`(4332.9418−4340.7550)/4340.7550×100 = −0.18` ✅
- **没有日期字段**
- 对个股（`s_sh600519`）、ETF（`s_sh510300`）、指数都一样有效
- **`f[1]` 点位为 0 是合法值**：开盘前深市指数（`s_sz399006` 创业板指 / `s_sz399303` 国证2000 / `s_sz399001` 深证成指）返回 `点位=0.00, 涨跌幅=0.00, 成交量=0`，而同时沪市 `s_sh000300` 有真实点位。**拿「点位 <= 0」当无效行会把深市指数整行丢掉** —— 这是本项目修过的一个真 bug。

### 3.2 A 股 / 北交所完整版 —— 34（沪）/ 33（深）字段
```
var hq_str_sh000300="沪深300,0.0000,4340.7550,4332.9418,...,2026-09-29,10:26:01,00,";
var hq_str_sz399006="创业板指,0.0000,3139.825,3138.700,...,2026-09-29,09:05:12,00";
```
```
[0]名称  [1]今开  [2]昨收  [3]现价/最新点位  [4]最高  [5]最低
[6]买一  [7]卖一  [8]成交量  [9]成交额
[10]买一量 [11]买一价 [12..19]买二~买五  [20..29]卖一~卖五
[30]日期  [31]时间  [32]状态位（沪市恒为 "00"）
[33] 沪市独有的尾部空字段（深市没有，故 34 vs 33）
```
> ⚠️ **`f[4]`/`f[5]` 是最高/最低，不是涨跌额/涨跌幅** —— A 股完整版**没有**现成的涨跌幅字段，
> 只能 `(f[3]−f[2])/f[2]` 自己算。实测印证：`sh000300` 的 `f[4]=4346.70 > f[3]=4335.07 > f[5]=4324.53`，
> 只能是最高/最低。（易错点：社区资料里偶有把 `[4][5]` 写成涨跌额/涨跌幅的转述，别照抄。）

- **指数和个股是同一套布局**，`(f[3]−f[2])/f[2]` 对两者都成立。⚠️ 别用「字段少的是指数」判形态 —— 指数完整版也是 33/34 字段；那个说法只在 `s_` 简版下成立。
- `f[30]` 日期、`f[31]` 时间，**sh / sz 位置一致**（实测）；沪 `f[33]` 是空串，**没有稳定契约，不要去读**
- **北交所 `bj` 字段数不固定**：`bj430047`/`bj872925` 是 33，`bj920445` 是 39（尾部多出真实数据）。也别按字段数判形态。
- **存在「格式完整但日期陈旧」的响应**：实测 `bj872925`（停牌）返回 `f[30]=2026-09-22`、7 天前，`f[2]=f[3]=0.000`，不是空串。所以日期兜底要**多标的投票取最新**（见 §6）。
- 完整版要保留 `现价 > 0` 守卫：盘前深市指数完整版 `f[3]=0.000`，不守卫会算出 **−100%**。
  副作用（实测、且是想要的）：停牌/长期无成交的代码全字段为 0（如 `bj430047` 返回 33 字段但 `f[2]=f[3]=0.000`）会被**整行跳过**，日志是「跳过 bj430047：昨收或现价无效」。注意这与简版不同 —— 简版的 0 点位要放过（§3.1），完整版的 0 现价要拦（否则 −100%）。

### 3.3 `int_` 海外指数 —— 4 字段
```
var hq_str_int_nikkei="日经指数,44946.64,-408.35,-0.90";
                        [0]名称 [1]现价 [2]涨跌额 [3]涨跌幅%
```
- **`f[3]` 直给涨跌幅**，别套 A 股完整版的 `(f[3]−f[2])/f[2]` —— 那里 `f[2]` 是昨收、这里是**涨跌额**，套上去会把日经 `-0.90%` 算成 `+0.02%` 这种**看着还挺像样**的垃圾。
- 涨跌幅小数位不统一：日经 `-0.90`（2 位）、恒生 `-0.600`（3 位）→ 统一 `round_change()` 归一到 2 位
- 没有日期字段

### 3.4 `hf_` 外盘期货 —— 15 字段（`hf_XAU` 14）
```
var hq_str_hf_NQ="30477.025,,30516.500,30517.750,30616.000,30430.000,10:26:53,
                  30566.250,30560.500,0,1,1,2026-09-29,纳斯达克指数期货,0";
```
```
[0]现价  [1]（hf_NQ 空 / hf_XAU 有值，语义不稳，别用）  [2]买价  [3]卖价
[4]最高  [5]最低  [6]时间 HH:MM:SS  [7]昨收  [8]开盘  [9]持仓  [10] ?  [11] ?
[12]日期  [13]中文名  [14]'0'（hf_XAU 没有这一位，故 15 vs 14）
```
- **没有现成涨跌幅**，必须自算 `(f[0]−f[7])/f[7]*100`（要求 `f[7] > 0`）。实测 `hf_NQ` 30477.025/30566.250 → `−0.29%`
- 名称取 `f[13]`（中文，只进日志，不上屏）
- `f[12]` **有**日期，但**故意不参与日期投票**（§6）
- 别按字段数判形态（`hf_XAU` 少一位）

### 3.5 `hk*` 港股 —— 19 字段
```
var hq_str_hkHSI="HSI,恒生指数,24648.640,24642.510,24648.640,24479.610,24507.299,
                  -135.211,-0.549,0.00000,0.00000,53762078,3320140923,0.000,0.000,
                  28056.100,22518.000,2026/09/29,10:23";
```
```
[0]英文名(ASCII: HSI/TENCENT/BABA-W)  [1]中文名  [2]今开  [3]昨收  [4]最高  [5]最低
[6]现价  [7]涨跌额  [8]涨跌幅%  [9]买价  [10]卖价  [11]成交量  [12]成交额
[13]/[14] 0.000  [15]52周最高  [16]52周最低  [17]日期 2026/09/29  [18]时间
```
- **`f[8]` 直给涨跌幅，不自算**。算术自校验：`(24507.299−24642.510)/24642.510 = −0.5487%` 与 `f[8]=−0.549` 吻合。与 `hf_` 正好相反。
- 有效性只认 `f[0]` 非空 + `f[8]` 可解析成有限数；**不拿现价 `f[6] <= 0` 当门槛**（同 §3.1 的盘前 0 原则）
- `f[17]` 日期是**斜杠格式**，与 A 股的 `2026-09-29` 混进同一个字符串 `max()` 会比错

### 3.6 `b_` 海外市场指数 —— 13 字段（`b_SPX` 6）｜ 至少延迟 15 分钟

```
var hq_str_b_DAX="德国DAX指数,25374.4200,-34.22,-0.13,9/26/2025,2025-09-26,
                   2026-09-29,11:38:25,25443.9800,25408.6400,25575.6600,25360.3200,45936176";
var hq_str_b_SPX="标准普尔500指数,7683.69,-59.72,-0.77,16:36:12,16:36:12";
                         ↑ b_SPX 只有 6 个字段（[0..5]），尾部没有 f[6]~f[12]
```
```
[0]名称  [1]现价/点位  [2]涨跌额  [3]涨跌幅%  [4]?  [5]?
[6]日期  [7]时间  [8]?  [9]昨收  [10]?  [11]?  [12]?
```

- **「至少延迟 15 分钟」是社区文档的说法**，本项目**未独立验证延迟幅度**。但 `b_` 的
  数据确实不适合拿来判「今天开没开盘」（见 §6）。
- ⚠️ **`b_SPX` 只有 6 字段 → 绝不能按字段数判形态**。13 字段是常态，不是契约。
- **`f[3]` 直给涨跌幅，不自算。** 算术自校验（两条独立样本互相印证）：

  | 代码 | 校验 |
  |---|---|
  | `b_DAX` | `25374.42 + 34.22 = 25408.64 = f[9]` → **f[9] = 昨收**；`-34.22 / 25408.64 = -0.13% = f[3]` ✅ |
  | `b_NKY` | `65219.72 + 657.90 = 65877.62 = f[9]`；`-657.90 / 65877.62 = -1.00% = f[3]` ✅ |

- `f[4]`/`f[5]` **语义未定，本项目不解析**：同一次请求里实测时而是
  `'9/26/2025'` + `'2:12 AM'`、时而是 `'2025-09-26'` + `'14:12:00'`、时而两空。
  看着像「日期 + 时间」的另一种表示，但两者与 `f[6]`/`f[7]` 的关系说不通。
- `f[8]`/`f[10]`/`f[11]` **推测**是今开/最高/最低（`最高 ≥ 现价 ≥ 最低` 看着成立），
  **但未确证 → 本项目不填**。dry-run 里显示 `--` 就是「没解析出来」，不是 0。
- `f[12]` 推测是成交量（`45936176`，也有报 `'0'` 的），**未确证 → 不填**。
- `f[6]` 确实带日期，但**不参与日期投票**（§6）。
- `s_b_DAX` 实测**空串** → 没有 `s_` 简版。

### 3.8 外汇/汇率 —— 3a 裸代码 11 字段 / 3b `fx_` 前缀 18 字段｜ **本项目只识别、不推算**

```
# 3a 裸代码，**没有前缀**：
var hq_str_USDCNY="11:38:01,6.7054,6.7055,6.7136,45,6.7087,6.7132,6.7087,6.7094,美元人民币,2026-09-29";
var hq_str_DINIW ="11:42:00,101.2448,101.2448,101.1885,997,101.1882,101.2643,101.1646,101.2448,美元指数,2026-09-29";
# 3b fx_ 前缀：
var hq_str_fx_susdjpy="11:41:58,157.310000,157.340000,157.350000,4100,157.400000,
                        157.580000,157.170000,157.310000,美元兑日元即期汇率,
                        -0.030000,-0.040000,0.002605,,163.980000,152.100000,,2026-09-29";
var hq_str_fx_susdcny="11:42:02,...,6.7052000000,6.7053000000,6.7118000000,43.0000000000,
                        ...,在岸人民币,-0.0983,-0.0066,0.0043,此行情由新浪财经计算得出,
                        0.0000,0.0000,,2026-09-29";
```
```
[0..9] 两种子形态同一套：[0]时间 [1]现价 [2]现价 [3]? [4]? [5]? [6]? [7]? [8]现价(==f[1])
        [9]中文名
3a:    [10]日期                                   ← 共 11 字段
3b:    [10]? [11]? [12]? [13]说明文字 [14]? [15]? [16]''  [17]日期   ← 共 18 字段
```

**⚠️ 硬性决策：识别出外汇形态就跳过，绝不推算涨跌幅。**

理由（本项目做过 15 秒差分实测）：
- 三个形态里**只有 `DINIW` 的 `f[1]`/`f[2]`/`f[8]` 在变**，其余字段全静态 →
  **无法可靠定位哪个是昨收**；
- `fx_` 的 `[10]`/`[11]`/`[12]`（实测 `-0.030000` / `-0.040000` / `0.002605`）
  语义也定不下来；
- 若误把 `f[2]` 当昨收、`f[3]` 当现价，`USDCNY` 会算出
  `(6.7136 − 6.7055) / 6.7055 = +0.12%` —— **一个看着挺像样的垃圾值**。正因它看着
  合理，最容易被误当成「解析成功」而静默上屏，所以宁可跳过也不猜。

跳过时的中文原因（写进日志）：
```
跳过 USDCNY：外汇/汇率形态（裸代码 11 字段）的涨跌字段语义未验证，暂不推算
跳过 fx_susdjpy：外汇/汇率形态（fx_ 前缀 18 字段）的涨跌字段语义未验证，暂不推算
```

**3a 没有前缀 → 不能靠前缀分流**，只能靠代码形状识别。本项目用的判据：
**整串都是 ASCII 大写字母、不含任何数字、长度 5~6**（覆盖 `DINIW` 5 / `USDCNY` 6 /
`CNYUSD` 6），`fx_` 那一支用前缀判。

> **为什么这条判据不误伤 A 股**：A 股代码**必然含数字**（`sh000300` / `sz399006` /
> `bj430047`），所以「无数字 + 全大写字母」不可能命中任何 A 股代码。
>
> **为什么必须排在 A 股完整版分支之前**：不拦的话 `USDCNY` 会掉进完整版分支，被当成
> 「昨收 `f[2]` / 现价 `f[3]`」算出上面的 `+0.12%`。这是本次最该防的错。

`3a` 的 `f[10]` / `3b` 的 `f[17]` 都有日期，但**不参与日期投票**（理由同上，§6）。

## 4. 大小写：非对称规则，别「顺手统一」

实测（新浪**对所有代码**都大小写敏感）：

| 写法 | 结果 |
|---|---|
| `sh000300` | ✅ 34 字段 |
| `SH000300` | ❌ 空串 |
| `Sz399006` | ❌ 空串 |
| `s_Sh000300` | ❌ 空串 |
| `hf_NQ` | ✅ 15 字段 |
| `hf_nq` | ❌ 空串 |
| `hkHSI` | ✅ 19 字段 |
| `hsi` / `hk_hsi` | ❌ 空串 |
| `int_nikkei` | ✅ 4 字段（本来就是全小写） |
| `b_DAX` | ✅ 13 字段（大写标名） |
| `gb_ixic` | ✅ 36 字段 |

**规则**（`normalize_symbol()`）：

| 代码形态 | 处理 |
|---|---|
| `^(sh\|sz\|bj)\d{6}$`（大小写不敏感判定） | **转小写**（`SH000300` → `sh000300`） |
| 其余（`hf_*` / `hk*` / `int_*` / `b_*` / `gb_*` / `fx_*` / 外汇裸代码 / `nf_*`） | **原样保大小写** |
| 前导 `s_` | 大小写不敏感地剥掉 |

⚠️ 外汇 3a 的裸代码（`USDCNY` / `DINIW` / `CNYUSD`）**必须保大写** —— 它们靠
「整串大写字母 + 无数字 + 长度 5~6」被识别成外汇形态（§3.8）；写成小写 `usdcny` 就
既不匹配外汇判据、又落进 A 股完整版分支被误算。

因为 `int_nikkei` 全小写、`hf_NQ` / `hkHSI` 必须大写，这条规则天生不对称 —— **代码里必须留注释**，
否则以后有人「统一成一种」就会把 `hf_NQ` 打死（症状：整拍 `未解析到有效行情` + 6 行重试噪音）。

## 5. 其它已实测的坑

| 坑 | 表现 |
|---|---|
| 无效代码返回 200 + 空串 | 不报错，静默少一行；「请求成功」≠「代码有效」 |
| 盘前深市指数点位 0 | 简版与完整版都是 0；拿它当无效行会丢行/算出 −100% |
| `hf_` 字段数 14 或 15 | 按字段数判形态会崩 |
| `bj` 字段数 33 或 39 | 同上 |
| `b_SPX` 只有 6 字段（`b_` 常态 13） | 按字段数判形态会漏掉它 |
| `gb_dji` 只有 30 字段（`gb_` 常态 36） | 同上 |
| **外汇 3a 裸代码没有前缀** | 靠前缀分流认不出来 → 会掉进 A 股完整版分支被误算成 `+0.12%` 这种像样的垃圾。必须靠代码形状（无数字 + 全大写 + 长度 5~6）拦，且**必须排在 A 股完整版之前** |
| `rt_` 25 字段但位置同 `hk*` | 靠字段数挡不住，只能靠**前缀名单**拦，否则静默拿延时价当实时价 |
| 陈旧但结构完整的日期 | `bj872925` 报 7 天前的日期 → 只信一个标的会把交易日误判成休市 |
| `nf_` 布局完全不同 | `nf_IF0` 50 字段、`f[30]='0.000'`（**不是日期**）→ 别对任何前缀盲取 `f[30]` |

## 6. 日期投票只用 A 股

`sina` 完整版的 `f[30]` 是行情日期，用来判「今天是不是交易日」（节假日兜底）：
**日期不等于今天 → 判休市**。

`SinaQuotes` 的做法：

1. 每拍请求里让**每个 A 股代码**都同时捎带一份完整版（`list=s_sh000300,sh000300` 两行都返回，所以一次请求就够）
2. **取所有完整版日期里最新的一天**（`max()`）：
   - 停牌标的的陈旧日期被更新的日期盖掉 → 不会把交易日误判成休市
   - 节假日时全员报同一个上一交易日 → `max` 仍是那天 → 正确判休市（`max` 不会掩盖真正的休市）
3. **`int_` / `hf_` / `hk*` / `b_` / `gb_` 五种非 A 股形态一律 `date=""` 不参与投票**（外汇根本不出行），两条理由：
   - 交易日历不同（外盘 / 港股 / 美股 / 海外指数各有各的假期），混判会把节假日或非交易日误判成开市。`b_` 还多一层：它本身就是**延迟数据**，拿它判「今天开没开盘」在语义上就不成立
   - 日期格式不同：`hk*` 是斜杠 `2026/09/29`，`gb_` 的 `f[3]` 是**日期时间合一**的 `2026-09-29 08:02:08` → 混进同一个 `max()` 会按字符串序比错
   - 后果：纯非 A 股列表 `data_date` 为 `None`（`--stock-dry-run` 显示「行情日期 (取不到)」）

另有两条与日期投票配套的本地时间策略（`--market-open/--market-close`，默认 09:20~15:30 半开区间），
见 `push_auto.py` 顶部 docstring 与 `AGENTS.md`。

## 7. 代码段规律（哪些是指数）

新浪没有「指数清单接口」，代码得自己点。可用的判据：

- **`sh000xxx`** → 沪市/中证在沪挂牌的**指数**（000300 沪深300、000905 中证500、000688 科创50、000016 上证50、000852 中证1000）
- **`sz399xxx`** → 深市/深证信息**指数**（399001 深证成指、399006 创业板指、399303 国证2000、399673 创业板50）
- 沪市 ETF/基金是 `5xxxxx`（`sh510300` 沪深300ETF、**首位是 5 不是 6**）
- 沪市 A 股是 `6xxxxx`（`sh600519` 茅台、688 科创板）
- B 股：`sh900xxx`、`sz200xxx`
- **同一个数字在不同市场含义不同**：`sh000001` 是上证指数，`sz000001` 是平安银行

⚠️ 常见错误规律（实测反例）：「`6` 开头 = 基金」❌（`sh600519` 是股票）；「`9` 开头 = 指数」❌（`sh900901` 是云赛 B 股）；「非交易所挂牌指数（`sh932000` 中证2000）新浪能取」❌（空串）。

**要「只推指数」最稳的是白名单**（本项目就是这么用的），别靠代码段规律外推。

## 8. 我们代码里的对应位置

| 概念 | 位置 |
|---|---|
| 前缀常量 | `A_SHARE_PREFIXES`（只管转小写）/ `SIMPLE_PREFIXES`（管简版，`sh`/`sz`）/ `NOSIMPLE_PREFIXES`（`int_`/`hf_`/`hk`/`b_`/`gb_`/`fx_`）/ `UNSUPPORTED_PREFIXES`（`rt`） |
| 外汇代码形状判据 | `is_fx_symbol()`（+ `FX_PREFIX` / `FX_BARE_MIN_LEN` / `FX_BARE_MAX_LEN` / `FX_SKIP_REASON_*`） |
| 「只解析、暂时不用」的补充字段 | `SinaQuote` 的 `open`/`high`/`low`/`prev_close`/`volume`/`amount`/`quote_time`/`status`（全是带默认值的 `str`），由 `_optional_fields()` 按各形态**能确证的**填，取不到留 `""` |
| 大小写归一 | `normalize_symbol()` |
| 形态分流 | `SinaQuotes._parse_quote()` |
| 简版优先 / 完整版只贡献日期 | `SinaQuotes._parse()` |
| URL 构造（混用） | `SinaQuotes.build_url()` |
| 形态回归用例 | `python3 tools/push_auto.py --self-test`（82 条，含每种形态与每个坑） |

**注意 `A_SHARE_PREFIXES` 与 `SIMPLE_PREFIXES` 不是一回事**：`bj` 要转小写但**没有** `s_` 简版。
合成一个常量会让 `BJ430047` 静默取不到数据 —— 这两件事在代码注释与 self-test 第 66 条里都锁住了。
新增的 `b_` / `gb_` / `fx_` 实测**都没有** `s_` 简版（`s_b_DAX` / `s_gb_bili` / `s_fx_susdjpy` 均为空串），
所以 `SIMPLE_PREFIXES` **不用动**，只加进 `NOSIMPLE_PREFIXES`。

**注意外汇 3a 没有前缀、不在任何前缀常量里** —— 它靠 `is_fx_symbol()` 的代码形状判据识别，
且**必须排在 `_parse_quote` 的 A 股完整版分支之前**（self-test 73/75/78 锁住）。
外汇不出行，所以 `fetch()` 的 `{"name","change"}` 形状**不受影响**，设备 payload 一字未变
（self-test 81 锁住）。

## 9. 复核脚本（加新标的前先跑这个）

```python
import importlib.util
spec = importlib.util.spec_from_file_location("pa", "tools/push_auto.py")
pa = importlib.util.module_from_spec(spec); spec.loader.exec_module(pa)

codes = ["sh000300", "int_nikkei", "hf_NQ", "hkHSI", "bj430047"]   # 换成你要加的
code, raw = pa.http_request(pa.make_sina_url(pa.DEFAULT_SINA_URL, codes),
        headers={"User-Agent": pa.USER_AGENT, "Referer": pa.SINA_REFERER},
        encoding="gb18030", accept="*/*")
print("http=", code)
for line in raw.strip().splitlines():
    key = line.split("=")[0][len("var hq_str_"):]
    fields = line.split("=", 1)[1].strip().rstrip(";").strip('"').split(",")
    if len(fields) == 1 and not fields[0].strip():
        print("  %-14s EMPTY ← 无效代码" % key); continue
    print("  %-14s nf=%-3d %s" % (key, len(fields), fields[:6]))

rows, date = pa.fetch_quotes(pa.DEFAULT_SINA_URL, codes, 15, False)
print("解析:", rows)
print("行情日期:", date, "（只应来自 A 股行）")
```

或者直接用内置的（会额外打印开市判定与推送 payload）：

```bash
python3 tools/push_auto.py --stock-dry-run \
  --symbols sh000300,sz399303,int_nikkei,hf_NQ,hkHSI,b_DAX,gb_ixic,USDCNY,fx_susdjpy \
  --symbol-names CSI300,CNI2000,NIKKEI,NQ,HSI,DAX,IXIC,USDCNY,JPY
```

> `--symbols` 最多 5 个，所以上面这行要分两次跑（或者用 §9 开头那个复核脚本，它不限数量）。
> `fx_susdjpy` 有 10 字节、超过设备端 `name` 的 9 字节上限，**必须配简称**（这里配 `JPY`），
> 否则启动就报错；`b_DAX` 5 字节、`gb_ixic` 7 字节、`USDCNY` 6 字节则不需要。
> dry-run 会额外打一行「补充 …」显示**只解析、暂时不用**的字段（`--` = 没解析出来，不是 0），
> 外汇两行则会以「跳过 …：外汇/汇率形态的涨跌字段语义未验证，暂不推算」出现在 stderr。

## 10. 存疑 / 未实测

- `nf_*`（国内期货）逐下标含义**未实测**，只知道字段数 44~50 且 `f[30]` 不是日期
- `rt_*` 除 `rt_hkHSI` 外未逐一验证；本项目按前缀一律拒绝
- `hf_` 的 `f[1]`、`f[2]`、`f[3]`、`f[4]`、`f[5]`、`f[9..11]` 语义未逐一确认（本项目只用 `f[0]`/`f[7]`/`f[12]`/`f[13]`）
- `hk*` 的 `f[13]`/`f[14]` 恒为 `0.000`，语义未知
- `int_` 是否还有本项目未列举的代码（道琼斯/纳斯达克/标普/恒生/伦敦已验证）
- **`b_` 的「至少延迟 15 分钟」是社区文档的说法，本项目未独立验证延迟幅度**；实测只确认了「`b_` 的时间戳（`f[7]`）与 A 股不同步」
- **`b_` 的 `f[4]`/`f[5]` 语义未定**（同一请求里时而是 `'9/26/2025'+'2:12 AM'`、时而是 `'2025-09-26'+'14:12:00'`、时而全空）
- **`b_` 的 `f[8]`/`f[10]`/`f[11]`/`f[12]` 只是推测**（疑似今开/最高/最低/成交量），**未确证 → 本项目不填**
- **`gb_` 的 `f[24]`/`f[25]`（EDT 时间串）、`f[13]`/`f[14]`、`f[30..35]` 语义未定 → 不填**
- **外汇 `3a` 的 `f[3..7]`、`3b` 的 `f[10..16]` 语义未定 → 整个形态不推算涨跌幅**（见 §3.8）
- `fx_` 除 `fx_susdcny` / `fx_susdjpy` 外未验证；`3a` 只验了 `USDCNY` / `DINIW` / `CNYUSD`
- 成交量 `f[4]`（简版）单位：多家开源实现按「手」处理，成交额按「万元」，**本项目未实测**（盘中全 0），要用之前先在盘中验一次
